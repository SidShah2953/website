# siddhants.com

Personal writing site. Astro 5, fully static, no framework runtime. The design
brief and hard rules for working on it are in `CLAUDE.md`.

## Build

```
nvm use               # Node 24 (.nvmrc)
npm install           # also installs the pre-commit hook (.githooks/)
npm run dev           # local dev server; not for auditing (see CLAUDE.md)
npm run build         # static site into dist/
npm run check         # astro check (types)
npm run check:links   # every internal link and post PDF resolves
npx serve dist        # audit the built site; never with -s
```

`.env` holds local-only values (see `.env.example`). Production values live in
the Cloudflare Pages project, not in this repo or in GitHub.

## Deploy

Cloudflare Pages watches `main` and builds and publishes on its own. Merging to
`main` and pushing *is* the deploy; there is no other step and nothing to run.
GitHub Actions (`.github/workflows/ci.yml`) only checks types, builds and links;
a red run does not stop Cloudflare publishing, so treat it as "roll back or push
a fix". Branches other than `main` are never published.

`dist/_headers` is generated by `astro.config.mjs` at build time (Markdown
content types, canonical links, and a one-year immutable cache for the
content-hashed files under `/_astro/`). Cloudflare allows 100 rules; the build
warns at 90.

## Performance

The homepage's only heavy part is the hero surface (`src/components/Surface.astro`),
a single WebGL2 fragment shader that ray-marches a heightfield. It deliberately
uses no 3D library: three.js is about 121 KB gzipped, the whole homepage script
about 5 KB. What keeps it cheap:

- Draws only below the cut line (scissor), never above it.
- At most ~60 draws a second on 120 Hz screens; the motion is too slow to need more.
- Stops when the tab is hidden; one static frame under reduced motion; CSS
  gradient when WebGL2 is missing or the GPU drops the context.
- Shader compiles in the background (`KHR_parallel_shader_compile`) after first
  paint, so it never blocks the page loading.
- Resolution adapts to measured frame time and recovers when the GPU frees up.

The word map's drift stops whenever the map is off screen.

On touch screens the homepage moves one section per swipe (`src/scripts/sections.ts`);
desktop uses CSS scroll snap. Blog and other long pages scroll normally.

Measuring (against the built site, on this Mac):

```
npm run build && npx serve dist -l 4321
node scripts/checks/perf.mjs --runs 3             # LCP, CLS, INP, weight, frame times, GPU ms
git show main:src/components/Surface.astro > /tmp/old.astro
node scripts/checks/shader.mjs /tmp/old.astro     # shader cost + pixel diff vs another version
node scripts/checks/sections.mjs --n 120          # touch gestures: one section per swipe
node scripts/checks/edges.mjs                     # page edge colour vs the phone's bars
node scripts/checks/chrome.mjs                    # bar colour follows each section, down and back up
```

On the homepage the browser's bars follow the section on screen: each `.slide`
sets `--section-bg`, and the section controller copies the current one into
`--chrome` (html and body background, the veil's solid edges) and into
`theme-color`. A slide with its own background only needs to set that variable.

`perf.mjs` runs a phone profile (390x844 at 3x, 4x CPU throttle, slow 4G) and a
laptop profile (1440x900 at 2x), with analytics requests blocked. Frame times
depend on the GPU, so compare runs on the same machine only.

## What keeps working without Claude

- **Publishing**: push to `main`; Cloudflare builds and serves it. Nothing on
  this Mac needs to be running.
- **Post PDFs**: the pre-commit hook rebuilds changed post PDFs on commits to
  `main` made on this Mac. Commits from elsewhere skip it, and
  `npm run check:links` then reports any post missing its PDF.
- **Newsletter**: CI drafts a Kit broadcast for posts marked `newsletter: true`.
  Drafts only; sending is always manual.
- **Analytics**: GoatCounter and Cloudflare Web Analytics run in the browser;
  `analytics.siddhants.com` is a separate Cloudflare Worker (`subdomains/analytics/`).
- **The site itself**: static files on Cloudflare's CDN, no server, database or
  API key at runtime.

The owner-facing runbook (publish, update, takedown, settings) is in the
Obsidian vault at `Projects/Website/Website.md`.
